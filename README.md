# hxwl-10 考古探方记录

遗址探方、地层连续登记、出土物坐标档案与冻结修订的联审闭环。

## 技术栈

React 19 + Vite + TypeScript + 纯前端持久化（localStorage + JSON 导入导出）

## 本地运行

```bash
npm install
npm run dev      # 开发，端口 5110
npm run build    # 类型检查通过后产物构建
```

## 业务闭环

1. **建探方**：编号、遗址、开口尺寸（东西 × 南北），即坐标边界。
2. **连续登记地层**：自上而下按土色与深度登记；后一层顶深必须等于前一层底深，第 1 层自 0.00m 起，底深必须大于顶深。
3. **确认冻结**：草稿可改可删（只能从最新层逆序删）；确认后冻结，禁止直接改写。
4. **纠错修订**：冻结地层只能发起带原因的修订，系统先做上下邻层连续复核再立案；通过时新值生效，旧版（土色/顶深/底深）快照永久保留；撤回则旧版恢复。
5. **出土物入档**：必须选择已登记地层；坐标超出探方边界、或出土深度不落在所属地层（含修订后生效）区间，一律阻断，不产生悬空档案。
6. **刷新一致**：所有操作即时落盘 localStorage；每次刷新、导入都对整库重新联审。
7. **冲突列示**：每条冲突给出 触发规则 / 探方 / 地层 / 坐标 / 原值 / 说明。

## 规则一览

| 规则 | 含义 |
| --- | --- |
| S1 | 地层连续：后一层顶深 = 前一层底深（首层顶深为 0） |
| S2 | 底深必须大于顶深 |
| S3 | 层位必须连续，不得缺号 |
| S4 | 地层确认后冻结，不得直接改写/删除 |
| S5 | 纠错修订必须填写原因 |
| S6 | 出土物必须归属有效探方 |
| S7 | 出土物只能归入已登记地层 |
| S8 | 坐标不得超出探方边界 |
| S9 | 出土深度必须落在所属地层生效深度区间 |
| S10 | 修订候选值不得破坏与上下邻层的连续链 |

## 落盘与交换

- 自动持久化键：`hxwl-10.archaeology.db.v1`（含探方、地层、出土物、修订链、操作日志）。
- “落盘档案”页可导出完整 JSON 归档，或导入 JSON；导入成功后立即联审，损坏或非 v1 结构的文件会被拒绝且不覆盖现有档案。
- 内置一份零冲突样例（T0203/T0204 两探方），可随时恢复。

## 代码结构

```
src/types.ts   数据模型与冲突/结果类型
src/rules.ts   S1–S10 规则引擎：登记校验、修订链复核、全量联审
src/store.ts   落盘 store：操作、阻断日志、种子数据、JSON 导入导出
src/App.tsx    界面：总览 / 探方与地层 / 出土物 / 修订链 / 联审冲突 / 落盘档案
```
